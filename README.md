# phastr-bench

The experiments of the PHastR paper. They compare PHastR (from the [`sux`]
crate) with the reference implementation of PHast and PHast+ ([`ph`], from a
fork of [bsuccinct-rs] that fixes the multithreaded construction) and with
[PtrHash] (from a fork of its repository).

The two forks are git submodules pinned to the commits used for the paper,
so clone with `--recursive`:

```bash
git clone --recursive https://github.com/vigna/phastr-bench.git
```

(Or, after a normal clone, run `git submodule update --init --recursive`.)

All code, including the dependencies, is compiled for the local CPU
(`target-cpu=native`, see `.cargo/config.toml`).

## Quick check

```bash
cargo build --release
# PHastR built in memory and offline: prints "identical"
cargo run --release --bin offline -- -n 1000000 -m both
# PHastR, PHast+ with wrapping, and PtrHash on 10^6 keys
cargo run --release --bin cmp -- -n 1000000 -v r:8:10:4.25,ref:w3p:8:5.0,ptr:default
```

`cmp` compares any set of configurations (see the documentation at the
start of `src/bin/cmp.rs`):

- `r:<S>:<log2 L>:<λ>[:<log2 R>[:<storage>]]` for PHastR;
- `ref:<chooser>:<S>:<λ>` for PHast and PHast+;
- `ptr:<variant>[:<λ>]` for PtrHash.

Run any binary with `-h` for its options.

## Reproducing the experiments

```bash
nohup results/redo.sh &
```

`redo.sh` runs all the experiments of the paper. It needs Linux (it uses
`lscpu`, `free`, and GNU `time`). It builds the binaries in
`target-<hostname>` and writes the results to `results/<hostname>/`.
On a c7i.metal-24xl, with key sets up to 10⁹ keys (the default if there are
64 GB of free memory), it takes about eight hours. Key sets of 10¹⁰ keys must
be requested explicitly (`redo.sh 10000000000`): they need 250 GB of free
memory and about twenty more hours.

`redo.sh` runs these scripts, which can also be run one by one (their
usage is described at the start of each file):

- `run.sh`: single-threaded construction and queries (main table and
  space/time plots);
- `large.sh`: large key sets (bumped keys, thread scaling, memory);
- `spread.sh`: space over ten key sets;
- `offline.sh`: offline construction;
- `ablation.sh`: number of layouts;
- `strings.sh`: string keys.

The configurations are in `configs.sh`.

## Results

`results/c7i/` contains the results of the paper, obtained on an AWS
c7i.metal-24xl (see `env.txt`). The tables and plots of the paper are
generated by

```bash
results/tables.py results/c7i/run.csv results/c7i/spread.csv
results/large_tables.py results/c7i/large
results/plot_pareto.py results/c7i/run.csv
```
